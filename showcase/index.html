Jarvis · AI news agent · one real run

How Jarvis wrote today's digest

Every morning Jarvis picks the AI tools and tech news worth knowing for someone breaking into product management. It decides what to read, an editor model reviews its draft, and it rewrites until the draft passes. Below is one real run, step by step, with nothing edited.

01 · The run

What the agent decided to do

The model chose every step below. Code only carried out the tool calls and enforced the limits.

    02 · Self-review

    The editor rejected the first draft

    Each draft goes to two checks. Code rules can't be argued with: every story must be one Jarvis fetched, and at least 4 picks must be read in full. Then a separate Gemini call acts as a strict editor and scores the draft out of 10. A draft passes at 7 with no rule broken.

    03 · The fix

    What changed between drafts

    After the rejection, Jarvis read four articles in full, swapped a story the editor called weaker, and rewrote explanations around what the articles actually say.

    04 · The output

    The digest it produced

    Every link was fetched that morning. The model only ever sees story ids like s21; code turns them back into real links, so it can't invent one.

    06 · Design

    From workflow to agent

    Jarvis started as a fixed pipeline that emails me every morning in production. This version keeps that pipeline as a safety net and puts a model in charge of the steps.

    Before: pipelineNow: agent
    Who decides the stepsCode, in a fixed order: fetch, dedupe, one LLM call, sendGemini, choosing tools in a loop
    What the model readsHeadlines onlyHeadlines, plus full articles it chooses to open
    Quality checkNone. The first answer is sentCode rules + an editor model; rejected drafts come back with fixes
    A source goes downTries a fixed list of backup feed URLsSame, and can decide to search for the story elsewhere
    Model overloadedRun fails, alert emailSwitches to a backup model and carries on
    MemoryLinks already sentLinks already sent + lessons it writes for its next run
    • No invented linksStories are ids; code maps them to the URLs it fetched.
    • Web text is dataArticle text is labelled as information. No tool can act on it, and the only outside action is one email to a fixed address.
    • Hard budgets30 model steps, 12 article reads, 4 searches and 3 drafts per run, enforced in code.
    • Always deliversIf the agent fails, the original pipeline writes the email, so a bad day never means no digest.
